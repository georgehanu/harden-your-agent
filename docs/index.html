Your agent works.
Now harden it.

Take a small TypeScript agent for a guesthouse and add, one lesson at a time, the defences a real product needs: boundaries, an intent anchor, a render and fetch policy, identity, idempotency, and memory you can trust. Each defence is a small module, switchable, and proved by a test you can run.

A real agent, not snippets

A staff assistant for a small guesthouse: an inbox, partner pages, bookings, a refunds ledger and notes on disk. Run it with npm start.

No API key to start

Every lesson and the app run in replay mode with pre-written model turns. The loop, the tools and all six defences are the real code. Add a key to run it live.

Each defence is a test

npm run harden-check runs a corpus of fixtures through the code-level defences with a pass/fail table, meant for CI.

The lessons

1 Where untrusted text gets in Where untrusted text gets in, and why a system prompt is not a boundary. 2 Keep the agent on task An intent anchor and normalisation keep the agent on the task you set. 3 What the screen and the fetch tool can give away The screen and the fetch tool are channels too. Lock both down. 4 Acting as whom Act as the signed-in person, with role rules checked in code. 5 Tools that must not run twice Make the tools that move money safe to retry, and hard to push past sense. 6 Memory you can trust Notes you can trust: a write gate, provenance, expiry, and pinned tools. + The hardening test suite The hardening test suite, and a one-page checklist for CI.

Run it in a minute

git clone https://github.com/georgehanu/harden-your-agent.git
cd harden-your-agent
npm install
npm run lesson1

Node.js 20 or newer. Then try npm start and open http://localhost:3100.
